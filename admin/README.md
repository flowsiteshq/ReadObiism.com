# Admin workspace preview

Open `http://127.0.0.1:5514/admin/` with the rebuild web proxy and local Worker running. The layout follows the CoolAdmin/ALG dashboard pattern, adapted to OBI-ISM. Run `node scripts/setup-local-admin.mjs` once to create an ignored `.dev.vars` containing a local administrator email and randomly generated password, then restart the local Worker. Open `.dev.vars` privately to read those credentials. If the file already exists, the script does not overwrite it; add `OBI_ADMIN_EMAIL` and a unique `OBI_ADMIN_PASSWORD` of at least 24 characters yourself. Never reuse local credentials in production or commit them.

The administrator session is separate from reader accounts, uses an HttpOnly cookie and is checked by the Worker. It is an initial single-admin development foundation, not a production-ready identity system. The static dashboard shell can still be downloaded without a session; it holds no private data. Every future data/action endpoint must enforce its own server-side permissions. Before production, review identity and recovery, MFA, least privilege, auditing, rate limiting, deployment and static-route protection. Support actions require verified support procedures and confirmation. The API status card checks only `/api/health`, not D1 or payment providers.

The overview, charts and searchable reader, purchase, gift, device, book catalogue and device-transfer tables query isolated local D1 through administrator-authenticated endpoints. Gift codes are masked to their last four characters; their full value is not returned. Counts represent records, not sales totals or physical-device verification. Password hashes, session tokens, device hashes and manuscript content are not returned. The bulk screen can create local-only simulated orders or Paystack and Stripe test checkouts; it cannot process live bulk payments. See `../../docs/BULK-ORDERS.md`. Content editing, an admin audit log and other administrative changes are not implemented.

Chart.js 4.5.1 comes from the supplied CoolAdmin template; its license is in `vendor/CHARTJS-LICENSE.txt`. Review the licenses of any other template assets before adding them.

## Payment settings

The payment settings page reports only whether the connected Worker has each secret loaded; it does not reveal values, validate keys with a provider, or read Cloudflare production secrets. On the loopback preview, an authenticated administrator can save Paystack and Stripe test secret keys and a Stripe test webhook signing secret into the ignored local `.dev.vars`. Blank fields leave existing entries alone. The local editor rejects live and public API keys; the signing-secret prefix does not distinguish test from live, so use the test webhook signing secret. The Worker must be restarted after changes. The key values never belong in git or the web bundle.

Local bulk test checkout returns to port 5514 for both providers. On return the local Worker verifies the payment with the selected provider before issuing a code. This local-only recovery does not replace webhooks on deployed Workers; provider webhooks cannot reach the local Worker without a public relay. Single-edition Stripe checkout still uses the production return URL. Production secrets must be configured separately in Cloudflare Workers & Pages under the deployed Worker's settings.
